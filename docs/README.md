# ACBP 算法学习文档 · 导航

这里是**给初学者看的算法文档**。10 份 Markdown 文档，一份讲一个主题，
从「先看清整张地图」开始，到「怎么让规则算得更快」结束。
不需要任何算法基础，按顺序读即可；用 VS Code、Typora 或任意 Markdown 阅读器打开都能看，
图片走相对路径 `architecture/`，离线可用。

> 文档里的参数、文件名和命令都按当前源码核对过。**参数默认值请以 `config/settings.py` 为准**，
> 源码更新后文档可能滞后，遇到不一致时以源码为准。

## 一、我该从哪开始

如果全读，按下面 5 步走，每一步都有明确目的：

| 步骤 | 读哪几篇 | 这一步解决什么 |
|---|---|---|
| 1 | **00** 算法体系总览 | 看懂「统一插座」：棋盘进去、落子出来，以及一次落子经过哪几层 |
| 2 | **03** 随机基线 | 用最短的一篇熟悉接口、合法步、随机种子，顺手把程序跑起来 |
| 3 | **02 → 01** | 先看确定性的对抗搜索（Alpha-Beta），再看统计式的 MCTS，两者对照最好懂 |
| 4 | **04 → 05 → 06 → 07** | 四种进化算法共用一个底座（04），后三篇只换「怎么产生下一代」 |
| 5 | **08 → 09** | 偏工程：外部引擎怎么接、规则层怎么加速；不改代码可以最后再看 |

**只想让程序跑起来**：读 00 + 03，然后直接看下面「常用命令」。
**只想理解算法**：读 00 → 03 → 02 → 01 → 04 即可，05—07 可按需选读。
**想改代码 / 加新算法**：读完 00 后重点看每篇的「代码在哪儿」和「动手试一试」两节。

## 三、每篇都长一个样

10 篇统一使用同一套 8 节骨架，读到第 2 篇之后就不用再适应结构了：

1. **这一篇讲什么** —— 一句话定义 + 读完能回答的 3 个问题
2. **先用直觉理解** —— 生活化类比，零术语
3. **跟着走一遍** —— 一个具体小例子，按编号把过程走完
4. **名词速查** —— 术语 / 大白话 / 在项目里的取值或位置
5. **原理、流程图与伪代码** —— 进阶内容，标注「可跳过」，含 2 张架构图
6. **代码在哪儿** —— 文件 → 关键函数 → 作用
7. **动手试一试** —— 可直接复制的命令，以及改参数会看到什么
8. **常见疑问与已知限制** —— FAQ + 如实写明短板

> **读不下去时的规则**：第 5 节标了「进阶提醒」，可以整节跳过，不影响后面理解。
> 第 2、3 节是每篇的核心，务必先读这两节。

## 四、全局名词总表

| 名词 | 大白话 |
|---|---|
| 规则层 | 负责「什么算合法」「什么时候算赢」，在 `core/` |
| AI / 算法层 | 负责「下哪一步」，在 `ai/`，共 8 种 |
| 统一接口 | `select_move(board, on_progress=None)` → `(row, col)` |
| 工厂 | 按算法名（如 `mcts`）取出对应 AI，在 `ai/factory.py` |
| 预算 | 允许 AI 想多久 / 想多少次，先到即停 |
| 强制预检 | 一眼能赢或必须挡的棋，不搜索直接落子 |
| 候选裁剪 | 只看已有棋子附近的落点，控制分支数量 |
| 评估函数 | 给局面打一个分，正数对我有利 |
| 适应度 | 进化算法里「这套下法摆完有多好」的分数 |
| 向量解码 | 把一串 0~1 小数换算成一串合法棋步 |
| push / pop | 原地落子与撤销，避免反复复制棋盘 |
| ThinkState | AI 边想边播报的进度，界面据此画进度条和候选高亮 |

## 五、常用命令速查

```bash
# 最省事：图形菜单里选棋种、模式、双方算法
python start.py

# 两个算法对打
python start.py --game gomoku --mode ai_vs_ai --p1-ai mcts --p2-ai alphabeta

# 随机基线跑通整条链路
python start.py --game othello --mode ai_vs_ai --p1-ai random --p2-ai random --seed 42

# 收紧预算，观察棋力 / 速度变化
python start.py --game gomoku --mode ai_vs_ai --p1-ai alphabeta --p2-ai random \
  --ab-depth 4 --seed 42

# 四种进化算法横向 PK（共用同一组 EVO_* 预算）
python start.py --game othello --mode ai_vs_ai --p1-ai iga --p2-ai de --evo-time 5 --seed 42
```

常用参数：`--game`（gomoku / othello / go / chess）、`--mode`、
`--p1-ai` / `--p2-ai`、`--ab-depth` / `--ab-time`、
`--mcts-iterations` / `--mcts-time`、`--evo-population` / `--evo-generations` /
`--evo-horizon` / `--evo-time`、`--seed`、`--debug`。
完整说明见项目根目录 [README.md](../README.md)。

> 本项目**没有难度分档**。所有 AI 都按 `config/settings.py` 里的最大努力预算全力思考，
> 想调强弱直接改预算。比较两种参数时记得加 `--seed`，否则随机性会干扰结论。

## 六、架构图

`architecture/` 下有 20 张 PNG 与 20 个同名的 VSDX，每篇文档引用其中 2 张：

- `00_system_arch` / `00_algo_flow`：系统分层与一次落子的决策链路
- `01_mcts_*` … `07_abc_*`：每个算法一张流程图（flow）+ 一张推理架构图（arch）
- `08_edax_*`：外部引擎调用流程与集成架构
- `09_bitboard_*`：位板规则计算流程与规则层加速架构

PNG 用于文档内显示，VSDX 是同名图的可编辑 Visio 源文件。
图注里标明了每张图对应的源文件；Markdown 里用相对路径引用，移动整个 `docs/` 目录不会失效。

## 七、文档维护说明

本目录**只放成品**：10 份 Markdown 文档、20 张 PNG、20 个 VSDX，以及本导航文件。
项目里不再保留文档生成脚本，需要修改内容时直接编辑对应的 `.md` 文件即可。

维护时请留意三条约定：

1. **每篇保持 8 节骨架**，新增内容放进对应章节，不要另起一套编号。
2. **参数与文件路径以源码为准**，尤其 `config/settings.py` 与 `ai/` 下的实现。
3. **如实写明限制**，不要把「已知短板」改成模糊表述；初学者需要知道算法的适用边界。
