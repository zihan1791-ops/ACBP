# 棋类综合对战平台（五子棋 · 黑白棋）

基于 **Python + pygame** 的模块化桌面对战程序，支持**人机大战**、**AI 算法 PK**、
**人人对战**与**大模型对局**；内置 **MCTS（蒙特卡洛树搜索）**、**Alpha-Beta 剪枝**
两类强化算法，并可接入 **DeepSeek 等大模型 API** 作为棋手参与对局。全项目采用
分层模块化设计，规则、AI、对局、界面相互解耦，关键逻辑均配有详细中文注释。

**升级要点**：取消难度分档（AI 统一按最大努力预算全力搜索）、围棋入口暂停、
算法层全面强化（候选裁剪 / 威胁预检与排序 / 迭代加深 / 启发式 rollout / 胜率选步）、
**AI 思考过程实时可视化**（进度条 + 棋盘候选高亮 + 阶段/深度/耗时/最佳步/胜率）、
**大模型对局**（游戏内输入 API Key 自动保存、人类/算法/大模型任意组合对战）、
**大模型+MCTS 混合棋手**（大模型提名少数候选分支，MCTS 在其内搜索验证）。

## 一、环境与运行

### 1. 环境要求

- Python 3.10 及以上（开发环境：Python 3.13）
- 依赖库：pygame

### 2. 安装依赖

在项目根目录 `hw-1/` 下执行：

```bash
pip install -r requirements.txt
```

### 3. 启动程序

```bash
python start.py
```

不传参数启动时进入**图形主菜单**，可视化选择棋种、模式、双方算法与棋盘尺寸。

## 二、调参方式（PyCharm 优先）

### 方式一：PyCharm 源码全局变量调参（默认推荐）

打开 `config/settings.py`，直接修改文件中的大写全局变量，保存后在 PyCharm 中
右键运行 `start.py` 即可生效。常用变量如下：

| 全局变量 | 含义 | 可选值 / 示例 |
|---|---|---|
| `GAME` | 棋种 | `'gomoku'` 五子棋 / `'othello'` 黑白棋；`None` 进菜单选择 |
| `MODE` | 对局模式 | `'human_vs_ai'` 人机 / `'ai_vs_ai'` 算法 PK / `'human_vs_human'` 人人；`None` 进菜单 |
| `PLAYER1_AI` | 黑方算法 | `'mcts'` / `'alphabeta'` / `'random'` / `'llm'`（大模型）/ `'llm_mcts'`（大模型+MCTS）；`None` 表示人类 |
| `PLAYER2_AI` | 白方算法 | 同上；`None` 表示人类 |
| `BOARD_SIZE` | 棋盘尺寸 | `None` 取棋种默认；五子棋 9/11/13/15，黑白棋 8 |
| `MCTS_ITERATIONS` | MCTS 每步迭代上限 | 整数（默认 5000） |
| `MCTS_TIME_LIMIT` | MCTS 每步思考秒数 | 浮点秒（默认 10.0，与迭代上限先到即停） |
| `AB_MAX_DEPTH` | Alpha-Beta 搜索深度 | 整数（默认 10） |
| `AB_TIME_LIMIT` | Alpha-Beta 每步思考秒数 | 浮点秒（默认 10.0） |
| `RANDOM_SEED` | 随机种子（可复现对局） | 整数；`None` 不固定 |
| `SAVE_RECORDS` | 终局自动保存棋谱 | `True` 保存 / `False` 关闭 |
| `RECORDS_DIR` | 棋谱保存目录 | 相对项目根，默认 `records` |
| `LLM_BASE_URL` / `LLM_MODEL` | 大模型接入 | 默认 DeepSeek 官方 + `deepseek-flash`，详见第五章 |

> 难度说明：本项目**不再划分 easy / medium / hard 档位**。AI 统一使用上述
> 「最大努力预算」全力搜索；想调整强度直接修改上表预算变量即可。

### 方式二：命令行参数（覆盖全局变量）

命令行显式传入的参数优先级高于 `settings.py` 全局变量；未传入则沿用全局变量：

```bash
# 示例：人机大战，五子棋 15 路，人类先手（不传 --p1-ai），MCTS 后手
python start.py --game gomoku --mode human_vs_ai --p2-ai mcts

# 示例：算法 PK，黑白棋 Alpha-Beta 对 MCTS，收紧搜索预算观察棋力变化
python start.py --game othello --mode ai_vs_ai --p1-ai alphabeta --p2-ai mcts --ab-depth 4 --mcts-iterations 2000

# 示例：大模型对局（需先在游戏内「大模型设置」配置 API Key）
python start.py --game gomoku --mode ai_vs_ai --p1-ai llm --p2-ai llm

# 示例：大模型提名 + MCTS 验证，对阵纯 MCTS
python start.py --game gomoku --mode ai_vs_ai --p1-ai llm_mcts --p2-ai mcts --llm-proposals 3
```

| 命令行参数 | 对应全局变量 | 说明 |
|---|---|---|
| `--game` | `GAME` | 棋种（仅 gomoku / othello） |
| `--mode` | `MODE` | 对局模式 |
| `--p1-ai` | `PLAYER1_AI` | 黑方算法 |
| `--p2-ai` | `PLAYER2_AI` | 白方算法 |
| `--board-size` | `BOARD_SIZE` | 棋盘尺寸 |
| `--mcts-iterations` | `MCTS_ITERATIONS` | MCTS 迭代上限 |
| `--mcts-time` | `MCTS_TIME_LIMIT` | MCTS 思考秒数 |
| `--ab-depth` | `AB_MAX_DEPTH` | Alpha-Beta 深度 |
| `--ab-time` | `AB_TIME_LIMIT` | Alpha-Beta 思考秒数 |
| `--seed` | `RANDOM_SEED` | 随机种子 |
| `--width` / `--height` | 窗口尺寸 | 自定义窗口大小 |
| `--save-records` | `SAVE_RECORDS` | 开启棋谱自动保存 |
| `--records-dir` | `RECORDS_DIR` | 自定义棋谱保存目录 |
| `--debug` | `DEBUG` | 开启调试日志 |
| `--show-log` | `SHOW_LOG` | 开启常规日志 |
| `--llm-model` | `LLM_MODEL` | 大模型模型名（默认 deepseek-flash） |
| `--llm-base-url` | `LLM_BASE_URL` | 大模型 API 基地址（OpenAI 兼容） |
| `--llm-timeout` | `LLM_TIMEOUT` | 大模型单次请求超时秒数 |
| `--llm-max-tokens` | `LLM_MAX_TOKENS` | 大模型单次最大输出 token 数 |
| `--llm-thinking` | `LLM_ENABLE_THINKING` | 允许大模型先思考再落子（默认关闭） |
| `--llm-proposals` | `LLM_PROPOSALS` | 「大模型+MCTS」每步提名的候选分支数（默认 3） |

## 四、AI 算法说明（强化版）

### 0. 统一「最大努力预算」（`config/settings.py`）

不再按难度切档。所有算法共享一组预算变量：`MCTS_ITERATIONS=5000`、
`MCTS_TIME_LIMIT=6.0`、`AB_MAX_DEPTH=6`、`AB_TIME_LIMIT=4.0`。
调参 = 直接改预算，强度与耗时成正比。

### 1. 候选裁剪与启发式（`ai/candidates.py`）

- **候选裁剪**：五子棋 / 围棋只搜索「已有棋子 2 格邻域」内的空位，
  分支因子从全盘 200+ 降到约 40~80，搜索质量显著提升；
- **成五点检测**：临时落子 + 连子统计，找出「下一手直接连成五」的位置；
- **防守点检测**：除连续活三（`XXX` 两端皆空）外，同时识别**跳三**
  （`X_XX` / `XX_X`，4 格内 3 子 1 空且两端皆空）的开放两端，作为
  MCTS 候选前置与 rollout 战术优先的强优先防守点；
- **启发式评分**：五子棋按「己方落子棋型分 + 对手落子防守分 ×1.3 + 邻域奖」、
  黑白棋按位置权重表打分，用于走法排序与 MCTS 先验。

### 2. Alpha-Beta 剪枝（`ai/alpha_beta.py`）

- **强制预检（四层）**：① 己方有成五点直接取胜；② 对手有成五点必须防守
  （冲四必挡）；③ 己方活三可成活四则抢先制造必胜威胁；④ 对手活三则堵住
  开放端，防止其形成活四；
- **迭代加深**：从第 1 层逐层加深到 `AB_MAX_DEPTH`，上层最优走法作为下层首选，
  配合 `AB_TIME_LIMIT` 超时即停，有限时间内拿到尽可能深的结论；
- **威胁排序**：按启发式分数降序搜索，高价值分支优先、更快触发剪枝；
- 叶子用 `evaluator` 评分，终局给 ±1_000_000 极端分。

### 3. MCTS 蒙特卡洛树搜索（`ai/mcts.py`）

- **选择**：按 UCT 公式逐层选择（探索常数收紧到 0.25，避免五子棋候选过多时
  访问被均匀打散），扩展时按启发式先验排序展开高价值分支，活三防守点前置；
- **模拟**：五子棋采用「短模拟 + 局面评估」——最多模拟 12 步，双方按战术贪婪
  （成五→堵五→成四→堵四，五级优先级）落子，未终局则用棋型评估打分映射胜率，
  避免长模拟被「随机凑五」噪声主导、防守价值被淹没；黑白棋按位置权重加权随机
  模拟至终局；
- **最终选步**：优先「访问次数达标者中胜率最高」的走法，否则退回访问数最多者，
  避免被噪声带偏；
- **强制预检**：与 Alpha-Beta 一致，四层（成五 / 堵五 / 活四进攻 / 堵活三）；
  其中「堵活三」层同时覆盖**跳三**（1011 / 1101，如 `X_XX` / `XX_X`）——
  跳三补中间空位即成连续活四，威胁等级与连活三一致，同样强制堵端；
- 支持「迭代次数 + 思考时间」双约束，先到即停。

### 4. 局面评估（`ai/evaluator.py`）

- 五子棋：四方向连子段长度 × 开放端棋型分——**双端被封死的连段按死型计接近
  0 分**（四连两端皆堵永远不会成五），让「堵住对手活三 / 活四」的防守价值
  能在评估中如实体现；
- 黑白棋：**位置权重差 ×10 + 机动性（合法步数差）×5 + 阶段子力**——
  中盘（子数 < 44）鼓励少子灵活、残局鼓励多子取胜，修正了旧版子力方向相反的问题。

### 5. AI 思考过程可视化（新增）

对局界面右侧新增「AI 思考中」面板，实时展示：

- **搜索进度条**：MCTS 按迭代数、Alpha-Beta 按加深层数实时推进；
- **统计行**：当前深度 / 最大深度、已处理迭代数（或搜索节点数）、已耗时；
- **当前最佳走法**：MCTS 显示胜率百分比，Alpha-Beta 显示评估分；
- **Top 候选**：访问数 / 胜率前三的走法列表，并在**棋盘上以彩色圆环高亮**
  （第 1 名强调色、第 2~3 名辅助蓝）；
- **提示行**：如「检测到对手冲四（N 处），强制防守」「检测到对手活三（N 处），
  堵端防守」「发现制胜点，直接成五」「己方活三成四，抢先制造活四」。

实现链路：`ai/think_state.py`（状态）→ 算法内定期更新 →
`game/controller.py step_ai(on_progress=...)` 透传回调 →
`ui/game_scene.py` 回调内实时 `draw + flip` 重绘画面。

## 五、大模型对局（新增）

主菜单的角色选项中新增「**大模型**」身份，可实现**人类 vs 大模型、
MCTS / Alpha-Beta vs 大模型、大模型 vs 大模型**等多种对局（先支持
DeepSeek 官方 API 的 `deepseek-flash` 模型，OpenAI 兼容协议，后续可
扩展到其它厂商）。

### 1. 配置 API Key（游戏内输入，自动保存）

主菜单点击「**大模型设置**」→ 在输入框中粘贴 API Key → 「保存」：

- Key **明文保存在本机** `config/llm_keys.json`，下次对局自动读取，
  无需重复输入；可在设置页随时修改 / 清除；
- 未配置 Key 时若选择大模型对局，轮到该方时会提示并**随机兜底一步**，
  保证对局不会卡死；
- Key 只用于调用你所填的 API 服务，不会上传到本游戏以外的任何地方。

### 2. 大模型如何走棋

- 每步把当前局面编码为文本发给大模型，内容包括：**文本棋盘**（带行列号，
  ● 己方 / ○ 对手 / · 空位）、双方子数、规则与策略、**战术要点**
  （成五点 / 必须堵的五点 / 可成活四的进攻点 / 必堵的活三端点；黑白棋额外给
  各步翻子数、可占角与对手可占角）、以及**优先落子清单**（战术点在前的
  24 个候选，其余只报数量）。模型对二维网格的理解远好于坐标元组列表，
  先替它把棋型算好，能显著减少「看不出对方活三」的漏防；
- 自动校验落子合法性，非法或请求失败自动重试
  （`LLM_MAX_RETRIES`，默认 3 次），仍失败则随机兜底；
  思考型模型偶发返回空 content 时，会回退解析 `reasoning_content` 里的
  结论坐标，减少无谓重试；
- 网络请求在后台线程执行，等待期间界面不冻结，并实时显示
  「等待大模型响应 N 秒」的进度提示（复用 AI 思考可视化面板）；
- 棋谱会记录大模型身份与具体模型名（如 `{"type":"ai","ai":"llm",
  "model":"deepseek-flash"}`），回放 / 续局照常支持。

> 实测结论：纯大模型（`llm`）没有搜索与强制战术校验，对 MCTS 会连续漏防
> 对手活三、被单向活四击败。要「能打」，用下面的 `llm_mcts` 混合棋手。

### 3. 大模型+MCTS 混合棋手（`llm_mcts`）

把大模型的棋理判断和 MCTS 的搜索验证串成两步：

1. **提名**：`LlmAI.propose()` 让大模型从战术要点里挑出至多 `LLM_PROPOSALS`
   个候选分支（默认 3 个，按模型给出的优先级排序）；
2. **验证**：`MCTSAI.set_restrict()` 把根节点分支限定在这几个点上，用完整
   迭代做模拟胜负验证，选出真正占优的一步；其余候选不参与搜索，等于把
   有限预算集中在模型认为值得算的分支上。

可靠性兜底：

- 模型调用失败或提名不足时，自动用启发式候选（邻域裁剪 + 棋理分）补齐；
- MCTS 的强制预检（能赢先赢、该挡必挡）在搜索前执行，命中即直接落子，
  不受提名限制影响——战术正确性优先于模型偏好；
- 所有候选点都经过棋盘合法性与根节点过滤，不会产生非法落子；
- 界面显示「大模型提名 N 个候选 → MCTS 验证」两阶段进度与根节点胜率。

角色选择里对应「**大模型+MCTS**」，命令行用 `--p1-ai llm_mcts --p2-ai mcts`。

### 4. 调参

`config/settings.py`（PyCharm 全局变量）或命令行（`--llm-model`、
`--llm-base-url`、`--llm-timeout`、`--llm-max-tokens`、`--llm-thinking`）：

| 全局变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LLM_BASE_URL` | `https://api.deepseek.com` | API 基地址（OpenAI 兼容） |
| `LLM_MODEL` | `deepseek-flash` | 模型名（DeepSeek V4.1-Flash） |
| `LLM_TIMEOUT` | `60.0` | 单次请求超时秒数 |
| `LLM_MAX_TOKENS` | `8192` | 单次最大输出 token 数（DeepSeek 合法范围 1~393216） |
| `LLM_ENABLE_THINKING` | `False` | 是否让模型先思考再回答；关闭时约 1 秒/步，开启后 20~40 秒/步且需更大 token 预算 |
| `LLM_MAX_RETRIES` | `3` | 失败 / 非法落子的重试次数 |
| `LLM_TEMPERATURE` | `0.2` | 采样温度（棋类建议低温度） |
| `LLM_KEY_FILE` | `config/llm_keys.json` | Key 保存文件 |
| `LLM_PROPOSALS` | `3` | 「大模型+MCTS」每步提名的候选分支数 |

## 六、棋谱自动保存与回放（新增）

### 1. 自动保存

每局棋**终局后自动**把完整棋谱写入 `records/` 目录（JSON 格式，UTF-8），
**按开局日期分文件夹永久保存**：

```
records/
└── 2026-11-03/            # 对局开局日期
    └── gomoku_20261103_203819.json
```

棋谱内容：

- **双方角色**：黑 / 白各自是人类还是 AI（AI 记录具体算法：MCTS /
  Alpha-Beta / 随机）；
- 棋种、棋盘尺寸、对局模式、先手方、AI 预算参数；
- **全部落子**：每步的落子方与坐标，含悔棋后的最终形态；
- 胜负结果、开局 / 结束时间。

棋谱只增不删，按天归档便于长期复盘；同名棋谱（如续局）自动追加序号，
绝不覆盖。关闭或改目录：`config/settings.py` 中 `SAVE_RECORDS` /
`RECORDS_DIR`，或命令行 `--save-records` / `--records-dir`。

### 2. 回放

主菜单新增「**棋谱回放**」按钮，进入后：

- **文件列表**：**递归扫描全部日期文件夹**，按时间倒序列出历史上所有棋谱
  （棋种 · 日期时间 · 手数 · 结果），翻页浏览、点击进入；
- **逐步回放**：复用对局场景的棋盘渲染，侧栏显示双方角色、播放进度与
  当前手；支持：
  - `←` / `→`：上一步 / 下一步；
  - `空格`：开始 / 暂停自动播放（每步 0.6 秒）；
  - `Esc`：返回文件列表；
- **从这继续对局（可指定 AI 介入）**：回放到任意一手时点击「从这继续
  对局」，进入**续局设置**——默认按棋谱还原双方角色，也可**重新指定**
  黑 / 白为人类或任意算法（选择 AI 即 AI 介入），确认后从该局面直接
  进入对局场景继续下；终局保存的新棋谱包含完整手数并另存（不覆盖原棋谱）；
- 底部提供「上一步 / 播放 / 下一步 / 返回列表 / 从这继续对局 / 返回主菜单」按钮。

## 七、操作说明

- **落子**：人类回合点击棋盘对应位置；合法空位以绿色圆点提示；最后一手有红棕圆环标记。
- **AI 思考**：AI 回合会实时显示思考进度条、阶段、耗时与候选高亮，等待其完成即可。
- **悔棋**：人机大战一次回退两步（人类 + AI 各一步）；算法 PK / 人人对战回退一步。
- **重新开始**：复原到开局局面，保留当前棋种、模式与算法配置。
- **模式联动**：主菜单选项随模式自动约束——人机大战保证恰好一方人类、
  一方 AI（选黑方 AI 时白方自动为人类，反之亦然）；算法 PK 双方只能选
  算法；人人对战双方固定为人类。
- **大模型设置**：主菜单点击「大模型设置」，输入 DeepSeek API Key 并保存，
  之后即可在角色中选择「大模型」参与对局（Key 自动保存，下次免输入）。
- **棋谱回放**：主菜单点击「棋谱回放」，选一局棋谱后可用 ←/→ 单步或
  空格自动播放；点「从这继续对局」可重新指定双方角色（含 AI 介入）续弈。
- **返回主菜单**：退出当前对局，重新选择棋种与模式。

## 八、围棋说明（入口暂停）

围棋（go）规则与 AI 代码保留兼容，但**当前版本已暂停开放入口**：
- 主菜单不再提供围棋选项；
- `--game go` 会被命令行参数校验直接拒绝；
- 棋盘规则代码（`core/go/board.py`）与测试保持可用，便于后续恢复。

暂停原因：围棋分支因子与局面复杂度远高于五子棋，统一最大努力预算下需要
更专业的搜索结构（如 AlphaZero 式网络评估），与当前项目定位不符。

## 九、常见问题

**Q：界面中文显示为方框？**
A：系统缺少中文字体。`ui/assets.py` 会依次匹配雅黑、黑体、Noto 等字体；
请确认 Windows 系统自带中文字体完整，或安装 Noto Sans CJK 后重启程序。

**Q：2K / 4K 高分屏（系统缩放 125% / 150%）下字体发糊？**
A：已内置高 DPI 适配：程序启动时声明进程 DPI 感知，并读取系统缩放系数，
将窗口、字号、间距与全部布局坐标按物理像素放大渲染（如 150% 缩放下
窗口为 1440×960 物理像素），文字与线条原生清晰、不再被系统位图插值放大。
无需手动设置。

**Q：AI 思考时界面会实时刷新吗？**
A：会。AI 计算期间界面通过进度回调实时重绘，玩家可以看到进度条、阶段、耗时、
最佳走法与棋盘上的候选高亮；思考结束后自动落子。若想降低等待，可调小
`MCTS_ITERATIONS` / `AB_MAX_DEPTH` 等预算。

**Q：棋谱保存在哪里？回放支持哪些操作？**
A：每局终局自动保存到 `records/` 按开局日期分子文件夹归档（`RECORDS_DIR`
可改），永久保存。主菜单点击「棋谱回放」可回放历史上所有棋谱：←/→ 单步、
空格自动播放、Esc 返回列表；「从这继续对局」可指定双方角色（AI 介入）续弈。

**Q：如何接入大模型对局？**
A：主菜单「大模型设置」输入 DeepSeek API Key 保存（明文存于本机
`config/llm_keys.json`，下次自动读取），回到主菜单把某方角色选为「大模型」
即可。默认模型 `deepseek-flash`（DeepSeek V4.1-Flash），可在 `settings.py`
改 `LLM_BASE_URL` / `LLM_MODEL` 接入其它 OpenAI 兼容服务商。未配置 Key 时
该方会提示并随机兜底，不会卡死对局。

**Q：纯大模型为什么打不过 MCTS？怎么让它变强？**
A：大模型每步只看一次局面、没有搜索、也没有强制战术校验，对手的活三 /
冲四很容易被漏掉；MCTS 每步上千次模拟，还有「能赢先赢、该挡必挡」的预检。
把角色选为「**大模型+MCTS**」（`llm_mcts`）即可：大模型只负责提名少数候选
分支，MCTS 在候选内做完整搜索验证，既保留棋理判断，又用模拟胜负兜住误判。
调 `LLM_PROPOSALS`（默认 3）可控制提名分支数。

**Q：为什么不再有难度档位？**
A：用户拍板统一按最大努力预算搜索；强度差异通过直接修改预算变量实现，
不再用「简单 / 中等 / 困难」做二次包装。

**Q：如何新增一种棋类或新算法？**
A：规则层继承 `core/base_board.py` 实现统一接口；AI 层继承 `ai/base_ai.py`
实现 `select_move(board, on_progress=None)`，并在 `ai/factory.py` 注册表中登记。
新算法如需可视化，在计算过程中更新 `self.think` 并周期性调用 `_emit(on_progress)` 即可。
