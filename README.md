# 棋类综合对战平台（五子棋 · 黑白棋）

基于 **Python + pygame** 的模块化桌面对战程序，支持**人机大战**、**AI 算法 PK**、
**人人对战**；内置 **MCTS（蒙特卡洛树搜索）**、**Alpha-Beta 剪枝**
两类搜索算法，以及**改进遗传算法 / 差分进化 / 粒子群 / 人工蜂群**
四类群体优化选步 AI，可在算法 PK 中任意对战。全项目采用
分层模块化设计，规则、AI、对局、界面相互解耦，关键逻辑均配有详细中文注释。

**升级要点**：取消难度分档（AI 统一按最大努力预算全力搜索）、围棋入口暂停、
算法层全面强化（候选裁剪 / 威胁预检与排序 / 迭代加深 / 启发式 rollout / 胜率选步）、
**AI 思考过程实时可视化**（进度条 + 棋盘候选高亮 + 阶段/深度/耗时/最佳步/胜率）、
**「棋谱刊物」界面改版**（1440×900 大画布、纸墨配色、放大字号、键盘可达、动效降级）、
**AI 计算多进程隔离**（搜索移到长驻 worker，主界面保持 60fps 不再卡顿）。

## 一、环境与运行

### 1. 环境要求

- Python 3.10 及以上（开发环境：Python 3.13）
- 依赖库：pygame

### 2. 安装依赖

在项目根目录 `hw-1/` 下执行：

```bash
pip install -r requirements.txt
```

### 3. 启动程序

```bash
python start.py
```

不传参数启动时进入**图形主菜单**，可视化选择棋种、模式、双方算法与棋盘尺寸。

## 二、调参方式（PyCharm 优先）

### 方式一：PyCharm 源码全局变量调参（默认推荐）

打开 `config/settings.py`，直接修改文件中的大写全局变量，保存后在 PyCharm 中
右键运行 `start.py` 即可生效。常用变量如下：

| 全局变量 | 含义 | 可选值 / 示例 |
|---|---|---|
| `GAME` | 棋种 | `'gomoku'` 五子棋 / `'othello'` 黑白棋；`None` 进菜单选择 |
| `MODE` | 对局模式 | `'human_vs_ai'` 人机 / `'ai_vs_ai'` 算法 PK / `'human_vs_human'` 人人；`None` 进菜单 |
| `PLAYER1_AI` | 黑方算法 | `'mcts'` / `'alphabeta'` / `'random'` / `'iga'` / `'de'` / `'pso'` / `'abc'`；`None` 表示人类 |
| `PLAYER2_AI` | 白方算法 | 同上；`None` 表示人类 |
| `BOARD_SIZE` | 棋盘尺寸 | `None` 取棋种默认；五子棋 9/11/13/15，黑白棋 8 |
| `MCTS_ITERATIONS` | MCTS 每步迭代上限 | 整数（默认 5000） |
| `MCTS_TIME_LIMIT` | MCTS 每步思考秒数 | 浮点秒（默认 10.0，与迭代上限先到即停） |
| `AB_MAX_DEPTH` | Alpha-Beta 搜索深度 | 整数（默认 10） |
| `AB_TIME_LIMIT` | Alpha-Beta 每步思考秒数 | 浮点秒（默认 10.0） |
| `RANDOM_SEED` | 随机种子（可复现对局） | 整数；`None` 不固定 |
| `SAVE_RECORDS` | 终局自动保存棋谱 | `True` 保存 / `False` 关闭 |
| `RECORDS_DIR` | 棋谱保存目录 | 相对项目根，默认 `records` |
| `WINDOW_WIDTH` / `WINDOW_HEIGHT` | 窗口逻辑尺寸 | 默认 `1440` / `900`（150% 缩放下为 2160×1350 物理像素） |
| `EVO_POPULATION` | 群体优化 AI 种群规模 | 整数（默认 30） |
| `EVO_GENERATIONS` | 群体优化 AI 最大进化代数 | 整数（默认 50） |
| `EVO_HORIZON` | 单个体向前推演步数 | 整数（默认 6） |
| `EVO_TIME_LIMIT` | 群体优化 AI 每步思考秒数 | 浮点秒（默认 8.0，与代数先到即停） |

> 难度说明：本项目**不再划分 easy / medium / hard 档位**。AI 统一使用上述
> 「最大努力预算」全力搜索；想调整强度直接修改上表预算变量即可。

## 四、AI 算法说明（强化版）

### 0. 统一「最大努力预算」（`config/settings.py`）

不再按难度切档。所有算法共享一组预算变量：`MCTS_ITERATIONS=5000`、
`MCTS_TIME_LIMIT=10.0`、`AB_MAX_DEPTH=10`、`AB_TIME_LIMIT=10.0`。
调参 = 直接改预算，强度与耗时成正比。

### 1. 候选裁剪与启发式（`ai/candidates.py`）

- **候选裁剪**：五子棋 / 围棋只搜索「已有棋子 2 格邻域」内的空位，
  分支因子从全盘 200+ 降到约 40~80，搜索质量显著提升；
- **成五点检测**：临时落子 + 连子统计，找出「下一手直接连成五」的位置；
- **防守点检测**：除连续活三（`XXX` 两端皆空）外，同时识别**跳三**
  （`X_XX` / `XX_X`，4 格内 3 子 1 空且两端皆空）的开放两端，作为
  MCTS 候选前置与 rollout 战术优先的强优先防守点；
- **启发式评分**：五子棋按「己方落子棋型分 + 对手落子防守分 ×1.3 + 邻域奖」、
  黑白棋按位置权重表打分，用于走法排序与 MCTS 先验。

### 2. Alpha-Beta 剪枝（`ai/alpha_beta.py`）

- **强制预检（四层）**：统一复用 `ai/candidates.py::gomoku_forced_move`——
  ① 己方有成五点直接取胜；② 对手有成五点必须防守（冲四必挡）；
  ③ 己方活三可成活四则抢先制造必胜威胁；④ 直接占掉「对手下一手能成活四」
  的点（覆盖连续活三两端，以及跳三 1011 / 1101 补中间空位），
  若无此类点再退回活三 / 跳三堵端；
- **迭代加深**：从第 1 层逐层加深到 `AB_MAX_DEPTH`，上层最优走法作为下层首选，
  配合 `AB_TIME_LIMIT` 超时即停，有限时间内拿到尽可能深的结论；
- **威胁排序**：按启发式分数降序搜索，高价值分支优先、更快触发剪枝；
- 叶子用 `evaluator` 评分，终局给 ±1_000_000 极端分。

### 3. MCTS 蒙特卡洛树搜索（`ai/mcts.py`）

- **选择**：按 UCT 公式逐层选择（探索常数收紧到 0.25，避免五子棋候选过多时
  访问被均匀打散），扩展时按启发式先验排序展开高价值分支，活三防守点前置；
- **模拟**：五子棋采用「短模拟 + 局面评估」——最多模拟 12 步，双方按战术贪婪
  （成五→堵五→成四→堵四，五级优先级）落子，未终局则用棋型评估打分映射胜率，
  避免长模拟被「随机凑五」噪声主导、防守价值被淹没；黑白棋按位置权重加权随机
  模拟至终局；
- **最终选步**：优先「访问次数达标者中胜率最高」的走法，否则退回访问数最多者，
  避免被噪声带偏；
- **强制预检**：与 Alpha-Beta 共用同一份四层预检（成五 / 堵五 / 活四进攻 /
  堵对手成活四）；第四层覆盖**跳三**（1011 / 1101，如 `X_XX` / `XX_X`）——
  补中间空位即成连续活四，直接占掉该点而不是只堵两端；
- 支持「迭代次数 + 思考时间」双约束，先到即停。

### 4. 局面评估（`ai/evaluator.py`）

- 五子棋：四方向连子段长度 × 开放端棋型分——**双端被封死的连段按死型计接近
  0 分**（四连两端皆堵永远不会成五），让「堵住对手活三 / 活四」的防守价值
  能在评估中如实体现；
- 黑白棋：**位置权重差 ×10 + 机动性（合法步数差）×5 + 阶段子力**——
  中盘（子数 < 44）鼓励少子灵活、残局鼓励多子取胜，修正了旧版子力方向相反的问题。

### 5. AI 思考过程可视化

对局界面右栏的「AI 演算」区实时展示：

- **搜索进度条**：MCTS 按迭代数、Alpha-Beta 按加深层数实时推进；
- **统一数据行**：已处理、耗时、深度 / 迭代、当前最佳（MCTS 显示胜率，
  Alpha-Beta 显示评估分）；
- **候选走法**：胜率前三的走法列表，并在**棋盘上以等宽序号标记**
  （第 1 名朱砂实心、第 2~3 名灰墨空心）；
- **阶段提示**：如「检测到对手冲四，强制防守」「发现制胜点，直接成五」。

右栏各区块高度**完全固定**（不随思考状态切换），并按本局 AI 数量分三种呈现：

- **人人对战**：演算区与候选区整块隐藏，棋谱栏扩展到 15 手；
- **人机大战**：单栏演算卡，人类回合保留该 AI 上一手的最终结论，不留空态；
- **算法 PK**：黑 / 白双栏对照，两位 AI 各自保留自己的数据，当前思考方以朱砂点亮，
  避免整块数值随回合切换而重置、跳动。

候选走法固定 3 个槽位并缓存，仅在落子时清空；进度条保留上一步终值，
棋盘上的候选标记不会每帧闪烁。

同步 / 降级路径：`ai/think_state.py`（状态）→ 算法内定期更新 →
`game/controller.py step_ai(on_progress=...)` 透传回调 →
`ui/game_scene.py` 回调内 `draw + flip` 重绘（按 80ms 限流）。
真实窗口默认走下一节的多进程路径。

### 6. 多进程调度（AI 计算与界面解耦）

早期 `step_ai()` 与 pygame 主循环同线程，AI 搜索（预算最长 10 秒）期间事件循环
完全停摆，窗口可能被系统判为未响应。现在由 `ui/ai_runner.py` 提供**一个长驻
worker 进程**：

- 主进程只跑 60fps 事件循环，可拖动窗口、点悔棋 / 重开、随时关闭；
- 每步只发送棋盘快照（实测 300～400 字节）+ 算法名 + 玩家编号 + 配置字典；
- worker 内用 `ai.factory.create_ai` 重建算法，进度按 80ms 限流经队列回传，
  主进程把字段写回 `ThinkState`，因此 `ui/game_scene.py` 的渲染代码完全不变；
- 落子统一由 `game/controller.py apply_ai_move()` 收尾（快照 / 棋谱 / 终局保存），
  并校验走子是否仍合法，避免悔棋 / 重开后把旧局面的棋下到新棋盘；
- 悔棋、重开、切换场景会作废在途任务（世代编号）；worker 异常或启动失败
  自动回退同步模式，保证对局不中断；退出时统一关闭 worker。

`GameScene._pump_ai()` 非阻塞地提交 / 轮询，原同步路径仍保留。

**模式开关**：`ACBP_AI_MODE=async|sync`。真实窗口默认 `async`；
`SDL_VIDEODRIVER=dummy`（无头 / 测试 / 截图脚本）默认 `sync`，保持既有测试语义。
程序启动与场景构造阶段会幂等预热 worker，把 Windows `spawn` 的一次性开销
挪出对局过程。

实测（9 路五子棋，MCTS 300 迭代）：同步模式一次 `update()` 阻塞 **1551.8ms**；
多进程模式主循环单帧最大 **1.4ms**、平均 **0.17ms**，进度回传与落子均正常。

**二次开局稳定性修复**：Windows spawn 下被 `terminate()` 的 worker 会残留
`multiprocessing.Queue` 内部信号量计数；若 `cancel()` 后复用旧队列，新 worker
会永久阻塞在 `task_q.get()`。此时 `busy=True` 且进程仍存活，原有回退条件不成立，
表现为「AI 大战终局后重开 / 再开一局，AI 一直不计算」。修复为：`cancel()`
默认重建一对干净队列、worker 意外退出时自动重建、`poll()` 优先返回终态且
只认当前世代、`GameScene` 增加「最大算法预算 + 6s」看门狗（超时换队列重试一次，
连续超时回退同步模式）。回归测试 `tests/ai_runner_regression_test.py`（24 项）。

### 7. 群体优化选步 AI（`ai/evolution/`）

新增四种可直接在主菜单 / 算法 PK / 回放续局中选择的 AI：`iga` 改进遗传算法、
`de` 差分进化、`pso` 粒子群、`abc` 人工蜂群。四者与 MCTS / Alpha-Beta 完全同构，
对外只有 `select_move(board, on_progress) -> (row, col)`；**个体编码、适应度、
对手模型、棋理先验、进化算子全部封装在算法内部**，对局层与界面层零感知。

**内部管线**：个体是长度 `EVO_HORIZON` 的实数向量（分量 ∈ [0,1)）→
`kernel.decode` 把每个分量映射成「当前局面候选步列表」的索引，按
「我走一步 → 对手按棋理分应一步」推演 → `fitness` 用终局胜负奖励或
`evaluator` 局面分打分 → 取最优个体解码出的第一步作为落子。每一步都取自
实时合法候选集，因此 DE 的差分变异、PSO 的速度更新、ABC 的邻域扰动等
连续算子无需改造，也不会产生非法着法。

- **棋理先验**：与 MCTS / Alpha-Beta 共用四层强制预检（成五 / 堵五 /
  活四进攻 / 堵对手成活四，含跳三 1101 / 1011 补中间点），命中直接返回；
  初始种群再注入成四点、活三防守点与启发式高分候选，避免纯随机起步。
- **对手模型**：每步后由一层贪心棋理分选出对手应手，避免只优化己方序列的
  「自嗨」策略。
- **算子差异**：GA = 锦标赛选择 + 均匀交叉 + 自适应高斯变异 + 精英保留 +
  停滞重启；DE = DE/rand/1/bin；PSO = 惯性权重线性递减全局版；
  ABC = 雇佣蜂 / 跟随蜂轮盘赌 / 侦察蜂重置。
- **预算与可视化**：代数上限与 `EVO_TIME_LIMIT` 先到即停；进度条按已评估个体数
  推进，右栏显示代数、最优适应度与 Top 3 候选，棋盘同步高亮。
- **棋种适配**：只依赖规则层的 `get_legal_moves` / `apply_move` / `copy` 与
  `candidate_moves`，五子棋、黑白棋通用。

回归测试：`python tests/evolution_ai_test.py`（42 项，覆盖工厂注册、命令行预算、
两种棋合法步、强制预检、超时、worker 配置路径与真实对局循环），
`python tests/forced_precheck_test.py`（47 项，覆盖 1101 / 1011 跳三、
连续活三、四层优先级与全部六种 AI）。

## 五、棋谱自动保存与回放（新增）

### 1. 自动保存

每局棋**终局后自动**把完整棋谱写入 `records/` 目录（JSON 格式，UTF-8），
**按开局日期分文件夹永久保存**：

```
records/
└── 2026-11-03/            # 对局开局日期
    └── gomoku_20261103_203819.json
```

棋谱内容：

- **双方角色**：黑 / 白各自是人类还是 AI（AI 记录具体算法：MCTS /
  Alpha-Beta / 随机）；
- 棋种、棋盘尺寸、对局模式、先手方、AI 预算参数；
- **全部落子**：每步的落子方与坐标，含悔棋后的最终形态；
- 胜负结果、开局 / 结束时间。

棋谱只增不删，按天归档便于长期复盘；同名棋谱（如续局）自动追加序号，
绝不覆盖。关闭或改目录：`config/settings.py` 中 `SAVE_RECORDS` /
`RECORDS_DIR`，或命令行 `--save-records` / `--records-dir`。

### 2. 回放

主菜单新增「**棋谱回放**」按钮，进入后：

- **文件列表**：**递归扫描全部日期文件夹**，按时间倒序列出历史上所有棋谱
  （棋种 · 日期时间 · 手数 · 结果），翻页浏览、点击进入；
- **逐步回放**：复用对局场景的棋盘渲染，侧栏显示双方角色、播放进度与
  当前手；支持：
  - `←` / `→`：上一步 / 下一步；
  - `空格`：开始 / 暂停自动播放（每步 0.6 秒）；
  - `Esc`：返回文件列表；
- **从这继续对局（可指定 AI 介入）**：回放到任意一手时点击「从这继续
  对局」，进入**续局设置**——默认按棋谱还原双方角色，也可**重新指定**
  黑 / 白为人类或任意算法（选择 AI 即 AI 介入），确认后从该局面直接
  进入对局场景继续下；终局保存的新棋谱包含完整手数并另存（不覆盖原棋谱）；
- 底部提供「上一步 / 播放 / 下一步 / 返回列表 / 从这继续对局 / 返回主菜单」按钮。

## 六、界面与操作

### 1. 界面视觉系统

- **风格**：杂志编辑 / 东方纸墨。暖纸白 `#F2EDE3`（60%）、宣纸面 `#FBF8F1`（30%）、
  朱砂 `#B63C25`（10%，单屏唯一强调色）；展示字华文宋体、正文等线、
  数据 Cascadia Mono 等宽。英文只保留算法名、坐标、编号与单位等数据标识。
- **画布**：默认 `1440×900` 逻辑像素，150% 缩放下为 `2160×1350` 物理像素；
  布局按基准等比缩放，`--width/--height` 改尺寸不会崩版。
- **版面**：左棋盘印等宽坐标与双线装帧，右栏分「回合状态 / AI 演算 / 候选走法 /
  棋谱」四区，各区高度固定，不随思考状态跳动。按对局模式切换呈现：人人对战隐藏
  演算与候选、棋谱扩到 15 手；人机大战单栏并显示 AI 上一手结论；算法 PK 双栏对照、
  当前思考方朱砂点亮。
- **可读性**：正文对比度 14.66:1、次级文字 4.90:1、朱砂 4.91:1（启动时控制台
  打印 `theme.qa_report()` 自检结果）；`INK_FAINT` 只用于装饰线，不承担文字。
- **动效**：一次编排好的错峰入场；`R` 键或环境变量 `ACBP_REDUCE_MOTION=1`
  关闭全部动效；AI 进度回调按 80ms 限流重绘，降低同线程计算期间的 CPU 占用。

### 2. 操作说明

- **落子**：人类回合点击棋盘对应位置；合法空位以淡墨小点提示，最后一手用朱砂四角括号标出。
- **轮到谁下**：右栏顶部以朱砂大字显示当前回合方，终局时该行直接显示对局结果。
- **AI 思考**：AI 回合实时显示搜索进度、阶段、耗时、当前最佳与 Top 候选，
  棋盘同步高亮候选点；等待其完成即可。
- **悔棋**：人机大战一次回退两步（人类 + AI 各一步）；算法 PK / 人人对战回退一步。
- **重新开始**：复原到开局局面，保留当前棋种、模式与算法配置。
- **模式联动**：主菜单选项随模式自动约束——人机大战保证恰好一方人类、
  一方 AI（选黑方 AI 时白方自动为人类，反之亦然）；算法 PK 双方只能选
  算法；人人对战双方固定为人类。身份被自动调整时，菜单会给出一行说明。
- **算法选择**：算法共 7 种，黑 / 白方一行并排显示 3 个（前一个 / 当前 /
  后一个），中间为当前选中；点击 `<` / `>` 循环移动选中项，也可直接点击
  三个可见选项中的任意一个。选项下方是一条分段横杠指示器，当前算法
  对应的一段朱砂高亮，切换时左右滑动。回放续局的「从这继续对局」同样适用。
- **键盘操作**：`Tab` / 方向键切换焦点，`Enter` 确认；焦点项显示四角括号与朱砂竖条。
- **棋谱回放**：主菜单点击「棋谱回放」，选一局棋谱后可用 `←`/`→` 单步或
  空格自动播放，`Esc` 返回列表；点「从这继续对局」可重新指定双方角色（含 AI 介入）续弈。
- **返回主菜单**：退出当前对局，重新选择棋种与模式。

## 七、围棋说明（入口暂停）

围棋（go）规则与 AI 代码保留兼容，但**当前版本已暂停开放入口**：
- 主菜单不再提供围棋选项；
- `--game go` 会被命令行参数校验直接拒绝；
- 棋盘规则代码（`core/go/board.py`）与测试保持可用，便于后续恢复。

暂停原因：围棋分支因子与局面复杂度远高于五子棋，统一最大努力预算下需要
更专业的搜索结构（如 AlphaZero 式网络评估），与当前项目定位不符。

## 八、常见问题

**Q：界面中文显示为方框？**
A：系统缺少中文字体。`ui/assets.py` 使用三套配对字体：展示字华文宋体 /
思源宋体、正文等线 / 思源黑体、数据 Cascadia Mono 等宽；中英混排由
`mixed()` 按字符分字体渲染，避免等宽字体把中文画成方块。请在 `ui/fonts/`
放入对应字体文件，或确认系统字体目录已安装这些字体后重启程序。

**Q：2K / 4K 高分屏（系统缩放 125% / 150%）下字体发糊？**
A：已内置高 DPI 适配：程序启动时声明进程 DPI 感知并读取系统缩放系数，
全部布局坐标与字号按物理像素原生渲染。默认画布 `1440×900` 逻辑像素，
150% 缩放下窗口为 `2160×1350` 物理像素（适合 2560×1600 屏幕）；
`ui/theme.py` 的 `set_canvas()` 会让界面随 `--width/--height` 等比缩放，
自定义尺寸也不会崩版或出现大片空白。无需手动设置。

**Q：AI 思考时界面会实时刷新吗？会卡吗？**
A：会刷新，且真实窗口下不卡。进度由长驻 worker 经队列回传，主进程保持 60fps，
可拖动窗口、点按钮、随时关闭；玩家仍能看到进度条、阶段、耗时、最佳走法与
棋盘上的候选高亮。若 worker 启动失败会自动回退同步模式（此时仍会阻塞，但
游戏不中断），也可用 `ACBP_AI_MODE=sync` 主动切回。无头 / 测试环境默认同步。
若想降低等待，可调小 `MCTS_ITERATIONS` / `AB_MAX_DEPTH` 等预算。

**Q：棋谱保存在哪里？回放支持哪些操作？**
A：每局终局自动保存到 `records/` 按开局日期分子文件夹归档（`RECORDS_DIR`
可改），永久保存。主菜单点击「棋谱回放」可回放历史上所有棋谱：←/→ 单步、
空格自动播放、Esc 返回列表；「从这继续对局」可指定双方角色（AI 介入）续弈。

**Q：为什么不再有难度档位？**
A：用户拍板统一按最大努力预算搜索；强度差异通过直接修改预算变量实现，
不再用「简单 / 中等 / 困难」做二次包装。

**Q：如何新增一种棋类或新算法？**
A：规则层继承 `core/base_board.py` 实现统一接口；AI 层继承 `ai/base_ai.py`
实现 `select_move(board, on_progress=None)`，并在 `ai/factory.py` 注册表中登记。
新算法如需可视化，在计算过程中更新 `self.think` 并周期性调用 `_emit(on_progress)` 即可。
